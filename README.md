# แอพคุณหมอใจดี — โดย Pettinee

**Batch รายวัน:** `npm.cmd run automate:batch` หรือ `Run-Pettinee-Batch.cmd` อ่านครั้งละ 40 โพสต์ ถ้ายังไม่ถึงช่วงข้อมูลเดิมจะอ่านชุดถัดไปต่อเอง ไม่ย้อนอ่านชุดแรก เมื่อถึงเกณฑ์จะบันทึกรายงานและปิด Chrome ข้อมูลเก็บใน SQLite เดิม ดู [วิธีใช้ Batch และขีดจำกัด](docs/BROWSER-COLLECTOR.md) ยังไม่ได้ตั้ง scheduled task หรือเวลาเรียกงานให้อัตโนมัติ

**ตัวอ่านโพสต์อัตโนมัติบนเครื่อง:** รัน `npm.cmd run automate` หรือดับเบิลคลิก `Start-Pettinee-Automation.cmd` เปิด Chrome โปรไฟล์ worker แยกสำหรับกลุ่มที่ระบุ ผู้ใช้ล็อกอินเองเมื่อจำเป็น แล้ว worker อ่านข้อความ/ลิงก์จากหน้าเข้า SQLite และ ML เดิม Inbox อยู่ที่ <http://127.0.0.1:4187> มี outbox กันซ้ำ/restart, refresh 60 วินาที และสถานะรอล็อกอิน/element ไม่ตรง ไม่มีการส่งคอมเมนต์หรืออัปโหลดโพสต์ใหม่ขึ้นเว็บไซต์สาธารณะ อ่าน [วิธีใช้และขอบเขต Browser worker](docs/BROWSER-COLLECTOR.md)

เพิ่ม workflow ผู้ดูแลในโปรเจกต์เดิมตาม VPC กลุ่ม Mass: รับ event/นำเข้าโพสต์ → SQLite queue → Intent ML เดิม → Topic rules แยกส่วน → MiniLM จับคู่คู่มือเดิม → ร่างคำตอบสั้น → แก้ไขและอนุมัติ → คัดลอกหรือส่งผ่าน Page ที่มีสิทธิ์ มี Dashboard / Inbox / Settings และ Mock ที่วิ่งผ่าน pipeline จริง

**เริ่มทดลอง:** Node 22.13+ → `npm.cmd ci` → `npm.cmd run guides:download` → `npm.cmd start` → <http://127.0.0.1:4173> → ภาพรวม → รับ 1 โพสต์ → Inbox → อนุมัติและคัดลอก ไม่ต้องมี API key สำหรับ workflow นี้

ดู [วิธีใช้ คิว API และตัวแปรตั้งค่า](docs/WORKFLOW.md), [Facebook Page/Group และสิทธิ์](docs/FACEBOOK-INTEGRATION.md), [VPC coverage](VPC_COVERAGE.md), [.env.example](.env.example)

**สถานะจริง:** Core และ ML สองส่วนทำงานบน Node ร่างเป็นแม่แบบอิง metadata ไม่ใช่ LLM Page adapter ยังไม่มี credentials ให้เชื่อมจริง Group รอช่องทางที่มีสิทธิ์ Chatbot/Televet เป็นลิงก์ภายนอก **เว็บออนไลน์ด้านล่างยังเป็น static reader; Inbox server ต้องรัน Node บนเครื่องหรือ host ที่มี persistent disk**

```powershell

cd pettinee-ai-post-reader
npm.cmd ci
npm.cmd run guides:download
npm.cmd start
```

เปิด <http://127.0.0.1:4173> ดาวน์โหลดโมเดลครั้งแรกต้องใช้อินเทอร์เน็ต หลังจากนั้น ML ทำงานในเครื่อง น้ำหนักโมเดลและ tokenizer ไม่รวมใน Git แต่มี manifest ระบุ revision และ checksum ส่วนโมเดล Intent และดัชนีคู่มือพร้อมใช้งานอยู่ใน repo แล้ว

หน้าแรกเป็นหน้าเลือกโพสต์เต็มพื้นที่ ค้นหา เลือกหมวด บันทึก และแบ่งหน้าละ 24 โพสต์ กด **เปิดชุด 200 โพสต์** เพื่อตรวจและนำเข้าข้อมูลตัวอย่าง หรือเลือกไฟล์ Excel ของตนเอง ก่อนอ่านคู่มือหรือเตรียมข้อความถามต่อ ข้อมูลส่วนตัวที่กรอกในเว็บเก็บใน localStorage ของเบราว์เซอร์ ไม่ได้เขียนลง repo

ทดสอบด้วย `npm.cmd test` และ `npm.cmd run check` การเทรน Intent ใหม่ใช้ Python และแพ็กเกจใน `ml/requirements-lock.txt` เพิ่มเติม ดูคำสั่งใน [คู่มือ Intent ML](docs/INTENT-ML.md)

## ความสามารถและขอบเขตต้นแบบ

เพิ่ม **ML จำแนกความต้องการของโพสต์ที่เทรนจริง** แล้ว: TF-IDF ตัวอักษร + Logistic Regression ใช้ในเครื่องโดยไม่ต้องใช้ API key เปิดโพสต์แล้วกดจำแนก หรือไป **เครื่องมือข้อมูล → AI จำแนกโพสต์ / ตรวจป้าย** รายละเอียดผลทดลอง การตรวจป้าย และคำสั่งเทรนอยู่ใน [คู่มือ Intent ML](docs/INTENT-ML.md)

**รอบแรกฝึกจากป้ายร่างที่ผู้ช่วย AI จัดให้ ยังไม่ได้ให้คนตรวจครบ** คะแนนเป็นผลเทียบกับป้ายร่าง ไม่ใช่ความแม่นยำใช้งานจริง โมเดลไม่วินิจฉัยหรือประเมินความเร่งด่วน ส่วนคำตอบและสรุปในเว็บยังเป็น Demo แยกจาก ML นี้

เพิ่ม **หาคู่มือที่เกี่ยวข้องด้วย ML**: เปิดโพสต์แล้วพบส่วน “คู่มือที่อ่านต่อได้” อัตโนมัติ หรือกด “หาคู่มืออ่านต่อ” เพื่อพิมพ์เรื่องที่สนใจ ใช้โมเดล multilingual MiniLM ในเครื่องร่วมกับหัวข้อและคำที่ตรงกัน ค้นจากข้อมูลชื่อ/คำอธิบายคู่มือภาษาไทย 1,867 รายการ ตัวอย่างแผลบวมหลังทำหมันจับคู่กับคู่มือ `cat-post-neuter-recovery-care` ได้ รายละเอียดและวิธีอัปเดตอยู่ใน [คู่มือการจับคู่บทความ](docs/GUIDE-MATCHING.md) เป็นการค้นคู่มือความรู้ ส่วนการค้นโพสต์ที่ใกล้กันยังมีเพียง corpus ที่เตรียมไว้

หน้าถามต่อเปลี่ยนเป็นข้อความภาษาธรรมชาติให้อ่านก่อน กด “แก้ไขข้อความ” ได้ แล้วคัดลอกและเปิด MeongSilJang แยกกัน ไม่มีการส่งข้อมูลเคสอัตโนมัติ ผลตรวจล่าสุด **76 tests ผ่าน** รวม inference ของ ML จริง, ONNX WebAssembly, HTTP API, Excel, DOM flow ของรุ่นภายในเครื่อง/ออนไลน์ การคัดลอกข้อความ การปกปิดข้อมูล และการเพิ่มโพสต์ให้ผู้ใช้เดิม

อัปเดตโหมดโพสต์อย่างเดียว: หน้าแรกมีปุ่ม **เปิดชุด 200 โพสต์** จากไฟล์ใน `data/` เลือกชีต/คอลัมน์ให้อัตโนมัติ และมีหน้าอ่านแบบสั้น รายละเอียดขอบเขตข้อมูลและวิธีใช้ดู [โพสต์อย่างเดียว](docs/POSTS-ONLY.md) ผลตรวจล่าสุด 51 tests ผ่าน ข้อมูลเดิมยังเก็บไว้

เว็บภาษาไทยสำหรับทำความเข้าใจโพสต์จากกลุ่ม “ปรึกษาเรื่องแมว by ปอน” ต่อจาก `Pettinee_Feed_AI_Demo.html` เดิม ใช้บนเครื่องในโหมด Demo ได้โดยไม่ต้องมี API key และมีรุ่นออนไลน์พร้อมข้อความโพสต์ที่ตรวจปกปิดข้อมูล 179 รายการ แยกป้ายจากเคสจำลองชัดเจน

ปรับ UX/UI จาก VPC เมื่อ 19 พฤศจิกายน 2569: มีเรื่องส่วนตัว สมุดบันทึกพร้อมภาพ รายการจากแผนคลินิก ชุดคำถามค่าใช้จ่าย และตารางเทียบตัวเลือก โดยย้ายสถานการณ์ตัวอย่างไปที่ **เพิ่มเติม → เริ่มเรื่องใหม่ / ตัวอย่าง** เพื่อให้หน้าเลือกโพสต์เป็นงานหลัก ดูการเชื่อมปัญหาจากสไลด์กับหน้าจอและขอบเขตของ MeongSilJang ได้ใน [บันทึก UX/VPC](docs/UX-VPC-19Nov2026.md)

## เปิดเว็บบนเครื่อง

ใช้ Node.js 22 ขึ้นไป เครื่องนี้ติดตั้งแพ็กเกจ โมเดล และดัชนีไว้แล้ว เปิด PowerShell ในโฟลเดอร์นี้แล้วรัน:


ถ้าพอร์ต 4173 ถูกใช้อยู่ เลือกพอร์ตอื่นก่อนเริ่ม:

## นำเข้าไฟล์ TinyFish

ผู้ใช้เลือกไฟล์เองที่เมนู **เครื่องมือข้อมูล → นำเข้า Excel** ไฟล์ถูกอ่านในเบราว์เซอร์ ไม่อัปโหลดไป TinyFish หรือ server และไม่เรียก TinyFish API ขั้นนำเข้าสำเร็จเป็นคนละขั้นกับการเปิดผลวิเคราะห์

ไฟล์วิจัยที่ตรวจและใช้ทดสอบอยู่ที่:

```text
C:\intern\pettinee\17_11_26\Pettinee_Facebook_100_Posts_Research_17Nov2026.xlsx
```

พบห้าชีต:

- `เริ่มอ่าน`
- `100 โพสต์`
- `ตัวอย่างคอมเมนต์`
- `เปรียบเทียบ Solutions`
- `วิธีเก็บและข้อจำกัด`

ชีต `100 โพสต์` มีหัวตารางที่แถว 5 และข้อมูล 100 แถว เว็บเลือกชีตนี้ให้อัตโนมัติ แต่ผู้ใช้เปลี่ยนชีตและการเทียบคอลัมน์ได้ การเทียบที่ใช้กับไฟล์นี้คือ:

| ฟิลด์ในเว็บ | หัวคอลัมน์จริง |
| --- | --- |
| รหัสโพสต์ (postId) | ไม่ใช้คอลัมน์ — `ลำดับ` เป็นเลขลำดับชุดวิจัย ไม่ใช่ Facebook postId |
| หมวด | `หมวดหลัก (กำหนดโควตา)` |
| ข้อความโพสต์ | `สรุปโพสต์ (ถอดความ)` |
| ลิงก์ต้นทาง | `แหล่งข้อมูล (URL)` |
| ข้อความคอมเมนต์รายรายการ | ไม่ใช้คอลัมน์ — ไฟล์นี้ไม่มีข้อความต้นฉบับรายคอมเมนต์ |
| สรุปคอมเมนต์ | `สรุปคอมเมนต์ที่อ่านได้ (ถอดความ)` |
| สถานะการเก็บคอมเมนต์ | `สถานะคอมเมนต์` |

ไฟล์นี้มีสรุปคอมเมนต์ที่ใช้ได้ 82 โพสต์ และอีก 18 โพสต์ไม่มีข้อมูลคอมเมนต์ที่นำมาตรวจได้ ทั้ง 100 โพสต์ไม่มีคอมเมนต์ต้นฉบับรายข้อความ เว็บจึงระบุว่าเป็นข้อมูลถอดความและไม่เปิดการตรวจข้ออ้างรายคอมเมนต์ ชีต `ตัวอย่างคอมเมนต์` ก็เป็นข้อความถอดความเช่นกัน

ตรวจจำนวนโพสต์ใหม่ โพสต์ซ้ำ ข้อมูลขาด และตัวอย่างก่อนกด **ยืนยันนำเข้าข้อมูล** แถวที่มี postId หรือลิงก์โพสต์เดียวกันจะรวมเป็นโพสต์เดียว ลิงก์ Facebook ที่มี `comment_id` หรือรูปแบบ permalink ต่างกันยังใช้ระบุโพสต์เดียวกันได้ การนำเข้าไฟล์ซ้ำจะรวมข้อมูลที่เพิ่มมาแทนการสร้างโพสต์อีกใบ

จำนวนโพสต์ใหม่ขึ้นกับข้อมูลที่มีอยู่แล้ว เมื่อเริ่มจากชุด Demo ซึ่งมีข้อมูลถอดความสองโพสต์จากงานวิจัย การนำเข้าไฟล์วิจัยครบชุดควรพบ 98 โพสต์ใหม่และ 2 โพสต์ซ้ำ หลังนำเข้าแล้วซ้ำอีกครั้งควรพบ 0 โพสต์ใหม่และ 100 โพสต์ซ้ำ

ถ้าโพสต์ซ้ำมีข้อความหรือหมวดใหม่ เว็บแสดงข้อความล่าสุดที่นำเข้าพร้อมที่มาของข้อความนั้น และเก็บข้อความเดิมไว้ใน **ข้อความโพสต์จากแหล่งข้อมูลก่อนหน้า** คอมเมนต์จากหลายรอบรวมกันโดยไม่เพิ่มข้อความเดิมซ้ำ ผลวิเคราะห์เดิมของโพสต์ที่นำเข้าอีกครั้งจะถูกยกเลิกเพื่อไม่ใช้คำตอบจากข้อมูลเก่า

## สิ่งที่เป็น Demo และขอบเขต AI

- คำตอบใน Demo เป็นคำตอบและแม่แบบที่เตรียมไว้ล่วงหน้า ไม่มีการเรียกโมเดล AI
- เคสถอดความ #41 และ #100 อ้างที่มาจากชุดวิจัยตามเว็บเดิม ส่วนเคสผื่น การหาคลินิก การกิน/ขับถ่าย และการติดตามค่าใช้จ่าย เป็นเคสจำลอง 4 เคสที่ติดป้ายชัดเจน
- เคสตัวอย่างมีสรุปและทางเลือกที่เตรียมไว้เฉพาะเรื่อง เช่น ตารางวัสดุ แบตเตอรี่ และการถอดล้างของน้ำพุแมว
- โพสต์ที่นำเข้าใหม่ใช้แม่แบบทั่วไปซึ่งระบุข้อจำกัด ไม่อ้างว่า AI เข้าใจรายละเอียดเฉพาะเคสแล้ว
- ยังไม่มีแหล่งสัตวแพทย์หรือเกณฑ์ความเร่งด่วนที่ทีมอนุมัติ จึงไม่วินิจฉัย กำหนดขนาดยา แนะนำให้เปลี่ยนยา หรือจัดระดับความเร่งด่วน ใช้การระบุข้อมูลที่ขาดและเตรียมคำถามให้สัตวแพทย์แทน
- การตรวจรายคอมเมนต์ประเมินแต่ละข้ออ้าง มีเหตุผลและขอบเขตที่ใช้ได้ สถานะ “มีหลักฐานรองรับ” ต้องอ้างแหล่งที่ทีมอนุมัติ ซึ่งรายการปัจจุบันยังว่าง ไม่ใช้ยอดไลก์ จำนวนคนเห็นด้วย หรือคำตอบ AI เป็นหลักฐาน
- ผลวิเคราะห์ต้องผ่าน `validateAnalysis()` ก่อนแสดง รวมถึงตรวจว่าข้อความอ้างอิงมีอยู่ในคอมเมนต์ที่เก็บมาจริง

`GET /api/config` แจ้งว่า AI จริงยังไม่พร้อม ส่วน `POST /api/analyze` เป็นขอบเขตภายในของต้นแบบสำหรับต่อ adapter และตอบ 503 เมื่อยังไม่ได้ตั้งค่าผู้ให้บริการ ไม่ได้แสดงว่าเชื่อม AI สำเร็จ

หากเพิ่มผู้ให้บริการในอนาคต ให้ต่อ adapter ใน `server/provider.mjs` ผ่าน `createAppServer({ provider })` เก็บ API key ใน environment ฝั่ง server เท่านั้น และคงการตรวจ schema ก่อนส่งผลกลับ หน้าเว็บและ `config.js` ต้องไม่มี API key ข้อความโพสต์และคอมเมนต์ถูกส่งให้ adapter ในฐานะ `untrustedData` ไม่ใช่คำสั่งที่ระบบต้องทำตาม

## ถามต่อกับ MeongSilJang

กด **ถามต่อกับ MeongSilJang** หรือเลือกประเด็นใน **คำถามที่ยังไม่มีคำตอบ** เพื่อเปิดหน้าตรวจสรุป มีปัญหาหลัก สิ่งที่ลองแล้ว จุดที่เห็นต่าง ข้อมูลที่ยังขาด และคำถามหนึ่งข้อ ผู้ใช้แก้ข้อความก่อนกด **คัดลอกสรุป** จากนั้นกด **เปิด MeongSilJang** แยกกัน

แก้ URL ได้ใน `config.js` ค่าเริ่มต้นใหม่คือ `https://meongsiljang.com/th` สำหรับหน้าภาษาไทย และ `meongKnowledgeUrl` ใช้ `https://meongsiljang.com/ko/guide` สำหรับคลังความรู้ที่ตรวจพบเป็นภาษาเกาหลี เว็บไม่แนบข้อความเคสหรือข้อมูลส่วนบุคคลใน URL และตัด query กับ fragment ออกจากปลายทาง ไม่มีการส่งสรุปอัตโนมัติ ยังไม่ได้เชื่อม API หรือ deep link ของ MetaPet หากจะเพิ่มภายหลังต้องใช้เอกสารที่ MetaPet ยืนยัน ต่อผ่าน server และให้ผู้ใช้ตรวจข้อมูลก่อนส่ง

ในสมุดดูแล ผู้ใช้เลือก **สรุปไปคุยกับคลินิก** ได้ หน้าตรวจสรุปจะแสดงปลายทางเป็นคลินิกและซ่อนลิงก์เปิด AI ผู้ใช้คัดลอกไปใช้กับช่องทางคลินิกที่มีอยู่เอง ไม่ได้จองนัดหรือส่งข้อมูลให้คลินิกจากต้นแบบ

## ลอง UX จาก VPC

1. หน้าเริ่มต้นเลือก **เริ่มเรื่องของฉัน** เพื่อวางข้อความของตัวเอง หรือเลือกหนึ่งในห้าสถานการณ์เพื่อทดลองกับเคสที่ติดป้ายไว้
2. ที่ **เรื่องของแมว** กรอกข้อมูลที่ทราบ สิ่งที่กังวล และสิ่งที่ลองแล้ว เว้นข้อมูลที่ยังไม่ทราบได้
3. **บันทึกและภาพ** เพิ่มเวลาที่เห็น หัวข้อ และข้อความ แนบภาพ PNG/JPEG/WebP ได้ไม่เกิน 300 KB สูงสุด 6 ภาพต่อเรื่อง ภาพเก็บในเบราว์เซอร์ ไม่มี AI อ่านภาพและไม่มีภาพในข้อความที่คัดลอก
4. **แผนจากคลินิก** คัดลอกคำแนะนำที่ได้รับ เพิ่มเวลา/วันนัด และทำเครื่องหมายรายการ เว็บไม่สร้างแผนรักษาหรือตารางยาเอง และไม่ส่งแจ้งเตือน
5. **เตรียมเรื่องงบ** กรอกราคาที่ได้รับ ถ้ายังไม่ทราบให้เว้นไว้ ผลรวมจะบอกว่ามีราคากี่จากกี่รายการ เลือกประเด็นค่าใช้จ่ายเพื่อนำไปถามคลินิก
6. สถานการณ์อาหาร/อุปกรณ์มี **เทียบตัวเลือก** สำหรับสองตัวเลือก พร้อมงบและเงื่อนไขของบ้าน ไม่จัดอันดับแบรนด์หรือแต่งราคา
7. ตรวจและแก้สรุปก่อนคัดลอก เลือกถาม AI หรือเตรียมคุยกับคลินิก กลับมาจดสิ่งที่ได้คำตอบไว้ในสมุดดูแลได้

บันทึก/รายการจำกัด 100 รายการต่อเรื่อง ข้อมูลที่คุณกรอกอยู่แยกจากผล Demo และยังไม่ได้ยืนยันโดยสัตวแพทย์ เคสจำลองไม่ถูกเติมเป็นประวัติจริงในสมุดให้เอง

## การบันทึกข้อมูล

ข้อมูลโพสต์ที่นำเข้า โพสต์ที่บันทึก ผล Demo และประวัติรอบนำเข้าเก็บใน `localStorage` ของเบราว์เซอร์เครื่องนี้ เมื่อรีเฟรชหรือเปิด URL เดิมในโปรไฟล์เดิม ข้อมูลจะยังอยู่ ไม่มีฐานข้อมูล server หรือการซิงก์ข้ามเครื่อง หากล้างข้อมูลเว็บไซต์ เปลี่ยนโปรไฟล์ หรือเปลี่ยนพอร์ต จะไม่เห็นข้อมูลชุดเดิม พื้นที่เก็บของเบราว์เซอร์มีจำกัด เว็บจะแจ้งหากบันทึกถาวรไม่สำเร็จ

ข้อมูลเดิมใช้ key `pettinee-local-v1` ส่วนสมุดดูแลและภาพใช้ `pettinee-care-v1` โดยผูกกับรหัสโพสต์ ข้อมูลนำเข้าและโพสต์ที่บันทึกเดิมจึงยังใช้ได้ สมุดดูแลจะไม่ส่งข้อมูลไปรวมกับชุดวิจัยหรือ API โดยอัตโนมัติ

หน้าภาพรวมเก็บสำเนาข้อมูลตอนนำเข้าแต่ละรอบ ตัวเลขของรอบเก่าจึงไม่เปลี่ยนเมื่อโพสต์เดิมมีข้อมูลเพิ่มในรอบใหม่ แสดงจำนวนพร้อมฐาน เช่น `4 จาก 20 โพสต์` เฉพาะข้อมูลในรอบนั้น รายการ “ควรให้ทีมทบทวน” มาจากข้อมูลขาดหรือคอมเมนต์ที่ไม่ยืนยันว่าครบ ไม่ใช่เกณฑ์สุขภาพ เมื่อกดอ่านโพสต์จะเห็นข้อมูลล่าสุดที่รวมแล้ว คำถามซ้ำใน Demo นับข้อความที่ตรงกัน ยังไม่ได้จัดกลุ่มความหมายด้วย AI

## ทดสอบอัตโนมัติ

ชุดทดสอบ DOM ใช้ `linkedom` เป็นแพ็กเกจสำหรับทดสอบเท่านั้น ติดตั้งไว้แล้วใน workspace นี้ หากย้ายโปรเจกต์ไปเครื่องอื่นให้รัน `npm.cmd ci --ignore-scripts` ก่อนทดสอบ การเปิด Demo ด้วย `node server.mjs` ไม่ต้องใช้แพ็กเกจนี้

ผลตรวจล่าสุด 19 พฤศจิกายน 2569: ผ่าน **48 tests** (ตัวนำเข้า 14, ผล Demo และ schema 9, DOM flow 15, สมุดดูแล 4, server 6) พร้อม syntax check ครอบคลุมโมดูลใหม่ ตรวจ HTTP ของหน้าเว็บและไฟล์หลัก ไม่มีการ deploy การทดสอบ DOM จำลอง dialog/clipboard/การอ่านไฟล์ภาพ จึงไม่ใช่การตรวจ native browser หรือวิเคราะห์ภาพจริง

```powershell
npm.cmd test
```

หรือ:

```powershell
node --test tests/*.test.mjs
```

ทดสอบการอ่าน `.xlsx` จริง การหาหัวตาราง การรวมหลายแถว postId/URL การนำเข้าซ้ำ คอมเมนต์ไม่ครบ สรุปถอดความอย่างเดียว ข้อความที่มี HTML/คำสั่งแฝง การตรวจ schema และแหล่งอ้างอิง รวมถึงเส้นทาง server และกรณี AI ยังไม่ได้ตั้งค่า ชุดทดสอบ DOM ตรวจตั้งแต่เลือกไฟล์จนถึงแก้สรุปและส่งข้อความที่แก้แล้วให้ clipboard จำลอง รวมถึง URL ปลายทางที่ไม่มีข้อมูลเคส หากไม่พบไฟล์วิจัยตามพาธเดิม การทดสอบไฟล์วิจัยจะข้าม แต่ไฟล์จำลองใน repo ยังทดสอบได้ หากไฟล์อยู่ที่อื่นกำหนด `$env:RESEARCH_XLSX` เป็นพาธจริงก่อนรันทดสอบ

ข้อจำกัดการตรวจรับรอบนี้: ยังไม่ได้ยืนยันเส้นทางด้วยการคลิกจริงใน Chrome/Edge เพราะระบบควบคุมเบราว์เซอร์ของสภาพแวดล้อมทดสอบใช้งานไม่ได้ การทดสอบโมดูลและ DOM อัตโนมัติไม่ยืนยันพฤติกรรม clipboard การเปิดแท็บภายนอก หรือภาพที่เรนเดอร์จริงบนมือถือ จึงมีขั้นตอนตรวจในเบราว์เซอร์ด้านล่างสำหรับตรวจรับส่วนเหล่านี้

## ทดสอบครบเส้นทางด้วยตนเอง

1. เปิดเว็บแล้วเลือกโพสต์ เปลี่ยนหมวด ค้นหาคำว่า “น้ำพุ” บันทึกโพสต์ และเปิดหมวด **บันทึกไว้** รีเฟรชเพื่อตรวจว่ารายการยังอยู่
2. ไป **นำเข้า Excel** เลือก `tests/fixtures/import-demo.xlsx` ควรได้ 3 แถว รวมเป็น 2 โพสต์ โดยโพสต์น้ำพุมี 2 คอมเมนต์และสถานะเก็บได้บางส่วน ส่วนโพสต์คลินิกมีเพียงสรุปถอดความ
3. ตรวจและเปลี่ยน mapping ก่อนบันทึก ทดลองเลือก “ไม่ใช้คอลัมน์” ที่ข้อความโพสต์ เว็บควรแสดงคำแนะนำให้เทียบคอลัมน์และไม่ยอมบันทึกตัวอย่างเก่า กลับมาเลือกคอลัมน์ที่ถูกต้องแล้วกดยืนยัน
4. เลือกอ่านโพสต์ที่นำเข้า สถานะต้องบอก **นำเข้าสำเร็จ · ยังไม่ได้วิเคราะห์** กด **เปิดผลวิเคราะห์ Demo** แยกอีกขั้น แล้วอ่านสรุป ทางเลือก และข้อจำกัด
5. โพสต์ที่มีคอมเมนต์รายข้อความต้องแสดง **จากคอมเมนต์ที่เก็บได้** กดลิงก์คอมเมนต์ที่รองรับประเด็นและตรวจว่ากลับไปข้อความจริงได้ โพสต์ที่มีเพียงสรุปต้องระบุ **ข้อมูลถอดความ** และไม่สร้างการตรวจรายคอมเมนต์
6. เปิดเคสผื่นจำลอง ตรวจว่าคอมเมนต์เดียวถูกแยกเป็นหลายข้ออ้าง โดยข้อสรุป “ทายาแล้วไม่ดีขึ้น แปลว่ายาไม่ดี” มีเหตุผลอธิบายว่าข้อมูลยังไม่พอสรุปคุณภาพยา
