# ส่งคำตอบจาก Dashboard

## เปิด Demo

```powershell
npm.cmd run replies
```

เปิด <http://127.0.0.1:4187> → Inbox → เลือกโพสต์ → ตรวจและแก้คำตอบ → บันทึก → ทำเครื่องหมายตรวจแล้วและอนุมัติ → **ทดลองส่ง Demo** → ตรวจข้อความ → ทำเครื่องหมายยืนยัน → **ยืนยันส่ง Demo**

ระบบเก็บใบรับ Demo ใน SQLite แยกจากการส่งจริง โพสต์ยังเป็น “อนุมัติแล้ว · ยังไม่ตอบ” ไม่เพิ่มยอดตอบแล้ว ไม่เปิด Chrome ไม่ใช้ clipboard และไม่มีข้อความส่งไป Facebook เคสจำลองและข้อมูลนำเข้าสามารถทดลองทางนี้ได้

## เปิดตัวส่งจริงผ่าน Chrome

```powershell
npm.cmd run replies:live
```

ใช้ Dashboard URL เดียวกัน และ SQLite เดิม ปิด `automate` หรือรอ `automate:batch` จบก่อน เพราะใช้ Chrome โปรไฟล์ worker เดียวกัน ค่าเริ่มต้น `data/runtime/collector-profile` และกลุ่ม `1067156573375730` ตั้งค่าผ่าน `COLLECTOR_GROUP_URL`, `COLLECTOR_PROFILE_DIR`, `COLLECTOR_BROWSER_CHANNEL` และ `COLLECTOR_APP_PORT` ได้ การตั้ง `BROWSER_REPLY_ENABLED=true` จะเปิดตัวส่งนี้กับ `npm.cmd start` ด้วย ปกติปิดไว้

1. เลือกโพสต์จาก Group ที่มีลิงก์ตรงกับกลุ่มที่ตั้งไว้ ตรวจและอนุมัติร่างเวอร์ชันปัจจุบัน
2. กด **ส่งคอมเมนต์จริง** ระบบเปิดโพสต์ด้วย Playwright ใน Chrome บนเครื่อง ไม่ใช่ GPT คุมจอ ตรวจข้อความโพสต์และชื่อบัญชีจากช่องคอมเมนต์ ยังไม่กรอกหรือส่งข้อความในขั้นนี้
3. ตรวจชื่อบัญชี ลิงก์ต้นทาง และข้อความในหน้าตรวจส่ง ทำเครื่องหมายยืนยัน แล้วกด **ยืนยันส่งคอมเมนต์** เพียงครั้งเดียว โปรแกรมกรอกและกดปุ่มส่งให้ ไม่ต้องคัดลอกหรือสลับไปเปิดโพสต์เอง
4. ระบบตรวจข้อความ ชื่อบัญชี ลิงก์และรหัสคอมเมนต์จาก DOM ถ้าพบจึงบันทึกผล หากพบข้อความรออนุมัติกลุ่มจะแจ้งว่ายังไม่เผยแพร่สู่ผู้อ่านทั่วไป การพบในหน้าเว็บเป็นการยืนยันจาก DOM ไม่ใช่ API receipt

หาก Chrome รอ login/checkpoint ผู้ใช้ต้องทำเอง ระบบไม่ข้ามการยืนยันตัวตน ช่องคอมเมนต์ที่มีข้อความค้างอยู่จะไม่ถูกเขียนทับ ถ้าบัญชี หน้าโพสต์ หรือข้อความต้นทางเปลี่ยนหลังเปิดหน้าตรวจส่งจะไม่กดส่ง ต้องตรวจใหม่ ไม่มีคิวส่งทุกโพสต์อัตโนมัติ

## กันซ้ำและตรวจผล

- หน้าตรวจส่งใช้ ticket หมดอายุใน 5 นาที ผูกกับโพสต์ ร่าง และ revision ที่อนุมัติ ใช้ส่งได้ครั้งเดียว
- SQLite จองสถานะส่งก่อนเรียก Chrome ปุ่มซ้ำหรือคำขอพร้อมกันไม่สร้างการส่งซ้ำ
- ถ้าแน่ใจว่ายังไม่กดส่ง โพสต์กลับเป็นอนุมัติแล้ว ให้เปิดหน้าตรวจส่งใหม่
- ถ้ากดส่งแล้วแต่ไม่พบรหัสคอมเมนต์ จะเป็น **ยังไม่ทราบผลส่ง** และหยุดการส่งซ้ำ ผู้ดูแลต้องตรวจต้นทางแล้วระบุว่าพบหรือไม่พบคอมเมนต์ก่อน การกดส่งบนหน้าเว็บไม่รับประกันว่า Facebook รับหรือเผยแพร่แล้ว
- ถ้า server หยุดระหว่างส่ง งานที่ค้างเกิน lease 120 วินาทีเปลี่ยนเป็นยังไม่ทราบผล เมื่อ worker ตรวจคิวครั้งถัดไป

ตัวส่งใช้ DOM ภาษาไทย/อังกฤษที่ระบุช่องหลักและปุ่มได้แน่นอน ถ้า layout เปลี่ยน ปิดคอมเมนต์ หรือเห็นหลายช่องที่แยกไม่ได้ จะหยุดพร้อมเหตุผล ไม่สุ่มคลิก ไม่ใช้ Enter เป็นทางสำรอง และไม่ลองส่งซ้ำเอง

## โค้ดและการทดสอบ

`automation/comment-driver.mjs` คุม Chrome, `automation/comment-dom.mjs` อ่าน DOM, `server/comment-delivery.mjs` ผูกการยืนยันและกันซ้ำ, `server/workflow-store.mjs` เก็บผล, `lib/comment-ui.mjs` หน้าตรวจส่ง และ `/comment-preview`, `/comment-send` อยู่ใต้ API workflow ที่ใช้ operator authorization เดิม

```powershell
npm.cmd run check
npm.cmd run build:public
npm.cmd test
```

ทดสอบ Demo ตั้งแต่เลือก/อนุมัติโพสต์ → เปิดหน้าตรวจ → ยืนยัน → บันทึกใบรับ โดยใช้ HTTP/SQLite จริงและ DOM จำลอง ทดสอบ live controller กับ browser double รวมกรณีส่งสำเร็จ กดซ้ำ ร่างเปลี่ยน บัญชีเปลี่ยน ลิงก์ผิด ข้อความค้าง ปุ่มไม่ชัด ผลไม่ทราบ และรออนุมัติกลุ่ม **ไม่มีการโพสต์คอมเมนต์จริงระหว่างทดสอบ** จึงยังไม่ถือว่าตรวจรับการส่งจริงบน Facebook แล้ว

เว็บ public ที่ deploy เป็น static reader ยังใช้ตัวส่งนี้ไม่ได้ ต้องรัน Node และ Chrome บนเครื่องนี้ ข้อมูล runtime, Chrome profile, session และโพสต์ที่เก็บใหม่ไม่ถูกนำขึ้น Git หรือเว็บสาธารณะ
