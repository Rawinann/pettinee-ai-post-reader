# ส่งคำตอบจาก Dashboard

## เปิด Demo

```powershell
npm.cmd run replies
```

เปิด <http://127.0.0.1:4187> → Inbox → เลือกโพสต์ → ตรวจและแก้คำตอบ → **ทดลองส่ง Demo** (เฉพาะเคสจำลอง) ครั้งเดียว ไม่มีหน้าต่างยืนยันซ้ำ

ระบบเก็บใบรับ Demo ใน SQLite แยกจากการส่งจริง โพสต์ยังเป็น “อนุมัติแล้ว · ยังไม่ตอบ” ไม่เพิ่มยอดตอบแล้ว ไม่เปิด Chrome ไม่ใช้ clipboard และไม่มีข้อความส่งไป Facebook เฉพาะเคสจำลองแสดงปุ่ม Demo ข้อมูลจริงที่ยังไม่มีลิงก์ต้นทางที่รองรับจะแสดงปุ่มส่งที่ปิดไว้พร้อมเหตุผล

## เปิดตัวส่งจริงผ่าน Chrome

```powershell
npm.cmd run replies:live
```

ใช้ Dashboard URL เดียวกัน และ SQLite เดิม ปิด `automate` หรือรอ `automate:batch` จบก่อน เพราะใช้ Chrome โปรไฟล์ worker เดียวกัน ค่าเริ่มต้น `data/runtime/collector-profile` และกลุ่ม `1067156573375730` ตั้งค่าผ่าน `COLLECTOR_GROUP_URL`, `COLLECTOR_PROFILE_DIR`, `COLLECTOR_BROWSER_CHANNEL` และ `COLLECTOR_APP_PORT` ได้ การตั้ง `BROWSER_REPLY_ENABLED=true` จะเปิดตัวส่งนี้กับ `npm.cmd start` ด้วย ปกติปิดไว้

ใน Dashboard / Inbox / Settings มีแผง **Chrome worker สำหรับตอบคอมเมนต์**:

- **เปิด Chrome / ล็อกอิน** เปิดโปรไฟล์ worker และกลุ่มที่ตั้งไว้เพื่อให้ผู้ใช้ล็อกอินเอง ยังไม่กรอกหรือส่งคอมเมนต์
- **ตรวจสถานะ** อ่านสถานะหน้า Chrome ปัจจุบันโดยไม่รีเฟรช Facebook ไม่รบกวนการล็อกอิน ไม่รับรองว่าพร้อมส่งจนกว่าจะตรวจโพสต์และบัญชีจริง
- **ปิด Chrome** ปิดเฉพาะ Chrome ของตัวส่งเมื่อไม่ใช้ เปิดใหม่ได้จากปุ่มเดิม ไม่ปิด Chrome ส่วนตัว และไม่อนุญาตให้ปิดระหว่างตรวจหรือส่งคอมเมนต์

ไม่จำเป็นต้องเปิด Chrome ค้างไว้ ถ้ายังปิดอยู่ ปุ่มส่งจะเปิดให้เอง แต่ครั้งแรกหรือเมื่อ session หมดอายุต้องล็อกอินให้พร้อมก่อน ถ้ากดส่งแล้วติด login ให้ล็อกอินแล้วกดส่งอีกครั้ง ระบบไม่ส่งคอมเมนต์เองทันทีหลังล็อกอิน การปิด Chrome จะยกเลิก ticket ที่เตรียมไว้ ปุ่มเปิด/ปิดไม่ล้างร่างที่ยังไม่ได้บันทึกใน Inbox

รอบนี้ทำงานบนเครื่องเดียวกับ Node server เท่านั้น เว็บออนไลน์ static เดิมไม่มี backend และยังสั่ง worker นี้จากเว็บนั้นไม่ได้ หากจะใช้ออนไลน์ต้องเพิ่ม backend และช่องทางคิวงานระหว่าง server กับ worker ก่อน ไม่เปิด Chrome profile หรือ remote debugging port ต่อสาธารณะ

1. เลือกโพสต์จาก Group ที่มีลิงก์ตรงกับกลุ่มที่ตั้งไว้ อ่านและแก้ข้อความในช่อง **คำตอบ PetMommy**
2. กด **ส่งคำตอบไปโพสต์ต้นทาง** ครั้งเดียว การกดนี้ยืนยันให้ส่งข้อความที่เห็นในช่อง ระบบบันทึกข้อความที่แก้ อนุมัติ revision นั้นลงประวัติ แล้วตรวจต้นทางก่อนส่ง ไม่มีปุ่มบันทึก/อนุมัติ/คัดลอกแยก ไม่เปิด dialog ยืนยันซ้ำ
3. ระบบเปิดโพสต์ด้วย Playwright ใน Chrome บนเครื่อง ตรวจข้อความต้นทางและบัญชี ผูก ticket กับร่างที่อนุมัติ แล้วกรอกและกดส่งให้ ไม่ต้องคัดลอกหรือเปิดโพสต์เอง ระหว่างเตรียมส่ง ช่องข้อความเป็นแบบอ่านอย่างเดียว หากโพสต์หรือข้อความเปลี่ยน จะยกเลิกก่อนส่ง การติดล็อกอินไม่ทำให้ร่างที่เพิ่งบันทึกหาย
4. ระบบตรวจข้อความ ชื่อบัญชี ลิงก์และรหัสคอมเมนต์จาก DOM ถ้าพบจึงบันทึกผล พร้อมแสดงชื่อบัญชีและลิงก์คอมเมนต์ หากพบข้อความรออนุมัติกลุ่มจะแจ้งว่ายังไม่เผยแพร่สู่ผู้อ่านทั่วไป การพบในหน้าเว็บเป็นการยืนยันจาก DOM ไม่ใช่ API receipt

หาก Chrome รอ login/checkpoint ผู้ใช้ต้องทำเอง ระบบไม่ข้ามการยืนยันตัวตน ช่องคอมเมนต์ที่มีข้อความค้างอยู่จะไม่ถูกเขียนทับ ถ้าบัญชี หน้าโพสต์ หรือข้อความต้นทางเปลี่ยนระหว่างตรวจปลายทางกับส่งจะไม่กดส่ง ไม่มีคิวส่งทุกโพสต์อัตโนมัติ

## กันซ้ำและตรวจผล

- ขั้นเตรียมส่งใช้ ticket หมดอายุใน 5 นาที ผูกกับโพสต์ บัญชี ร่าง และ revision ที่อนุมัติ ใช้ส่งได้ครั้งเดียว
- SQLite จองสถานะส่งก่อนเรียก Chrome ปุ่มซ้ำหรือคำขอพร้อมกันไม่สร้างการส่งซ้ำ
- ถ้าแน่ใจว่ายังไม่กดส่ง โพสต์กลับเป็นอนุมัติแล้ว แก้ปัญหาที่แจ้งก่อนกดส่งใหม่
- ถ้ากดส่งแล้วแต่ไม่พบรหัสคอมเมนต์ จะเป็น **ยังไม่ทราบผลส่ง** และหยุดการส่งซ้ำ ผู้ดูแลต้องตรวจต้นทางแล้วระบุว่าพบหรือไม่พบคอมเมนต์ก่อน การกดส่งบนหน้าเว็บไม่รับประกันว่า Facebook รับหรือเผยแพร่แล้ว
- ถ้า server หยุดระหว่างส่ง งานที่ค้างเกิน lease 120 วินาทีเปลี่ยนเป็นยังไม่ทราบผล เมื่อ worker ตรวจคิวครั้งถัดไป

ตัวส่งใช้ DOM ภาษาไทย/อังกฤษที่ระบุช่องหลักและปุ่มได้แน่นอน ถ้า layout เปลี่ยน ปิดคอมเมนต์ หรือเห็นหลายช่องที่แยกไม่ได้ จะหยุดพร้อมเหตุผล ไม่สุ่มคลิก ไม่ใช้ Enter เป็นทางสำรอง และไม่ลองส่งซ้ำเอง

## โค้ดและการทดสอบ

`automation/comment-driver.mjs` คุม Chrome, `automation/comment-dom.mjs` อ่าน DOM, `server/comment-delivery.mjs` ผูกการยืนยันและกันซ้ำ, `server/workflow-store.mjs` เก็บผล, `lib/comment-ui.mjs` หน้าตรวจส่ง และ `/comment-preview`, `/comment-send` อยู่ใต้ API workflow ที่ใช้ operator authorization เดิม

```powershell
npm.cmd run check
npm.cmd run build:public
npm.cmd test
```

ทดสอบ Demo ตั้งแต่เลือก/อนุมัติโพสต์ → กดส่งครั้งเดียว → บันทึกใบรับ โดยใช้ HTTP/SQLite จริงและ DOM จำลอง ทดสอบ live controller กับ browser double รวมกรณีส่งสำเร็จ กดซ้ำ ร่างเปลี่ยน บัญชีเปลี่ยน ลิงก์ผิด ข้อความค้าง ปุ่มไม่ชัด ผลไม่ทราบ และรออนุมัติกลุ่ม รวมถึงการเก็บร่างที่ยังไม่บันทึกเมื่อยกเลิกระหว่างเตรียมส่ง **ไม่มีการโพสต์คอมเมนต์จริงระหว่างทดสอบ** จึงยังไม่ถือว่าตรวจรับการส่งจริงบน Facebook แล้ว

เว็บ public ที่ deploy เป็น static reader ยังใช้ตัวส่งนี้ไม่ได้ ต้องรัน Node และ Chrome บนเครื่องนี้ ข้อมูล runtime, Chrome profile, session และโพสต์ที่เก็บใหม่ไม่ถูกนำขึ้น Git หรือเว็บสาธารณะ
