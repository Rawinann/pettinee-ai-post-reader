# PetMommy: คำตอบธรรมชาติและวัดการกดอ่านคู่มือ

## สถานะที่ใช้งานได้

เพิ่ม LLM สำหรับเรียบเรียงคำตอบเป็นภาษา PetMommy และเพิ่มตัวนับที่ฝั่งไทยดูเองได้แล้วบน Node server รุ่นในเครื่อง ไม่ต้องเปลี่ยนระบบ ML จับความต้องการและค้นคู่มือเดิม ยังไม่ได้ fine-tune น้ำหนักโมเดล ไม่มีการเรียกงานฝึกแบบเสียเงินหรืออัปโหลดชุดข้อมูลฝึก

```powershell
npm.cmd run replies:ai
```

เปิด <http://127.0.0.1:4187> → Inbox → เลือกโพสต์ → **เขียนใหม่แบบ PetMommy** → ตรวจ/แก้ → อนุมัติ → ส่งคำตอบจาก Dashboard ตามเดิม คำตอบใหม่จะยกเลิกการอนุมัติเวอร์ชันก่อนเสมอ

คำสั่งนี้เปิด Ollama บนเครื่องเป็นค่าเริ่มต้น ใช้ `qwen2.5:7b-instruct` ที่มีติดตั้งอยู่แล้ว ไม่ดาวน์โหลดโมเดลเพิ่ม ไม่ใช้ API key การตรวจจริงใช้เคสจำลองหลังทำหมันและได้ผลจาก LLM แล้ว ส่วน OpenAI มี adapter และทดสอบด้วย response จำลอง ยังไม่ได้เรียก API จริงเพราะยังไม่มี key ใน server

## โทนภาษา

โครงคำตอบคือ **hook → info → URL** แต่ผู้อ่านไม่เห็นหัวข้อหรือแบบฟอร์ม เช่นผลจากการทดลองเคสจำลอง:

> เห็นแผลยังบวมอยู่ ก็อดห่วงน้องไม่ได้เลยนะคะ
>
> จากข้อความอย่างเดียวยังบอกสาเหตุหรือวิธีดูแลเฉพาะตัวไม่ได้ค่ะ ลองเล่าสิ่งที่สังเกตให้หมอที่ดูแลฟังนะคะ
>
> อ่านเพิ่มได้ที่นี่ค่ะ
> [คู่มือหลังทำหมัน](https://pettinee.meongsiljang.com/th/guide/qa/cat-post-neuter-recovery-care)

ตัวอย่างที่พี่หมอให้ใช้เพื่อเข้าใจน้ำเสียง ไม่เอาข้อความ “บ้านนี้แมวจร 6 ตัว” น้ำหนัก อายุ หรือประสบการณ์พาไปหาหมอมาเป็นข้อเท็จจริงของเคสอื่น Hook ใช้การรับความรู้สึกแทนการสร้างประสบการณ์ส่วนตัว ถ้าจะให้เล่าประสบการณ์จริง ต้องมีข้อมูลจากเจ้าของประสบการณ์และสิทธิ์ให้ใช้ก่อน

LLM ได้อ่านข้อความโพสต์เป็นข้อมูลที่ไม่น่าเชื่อถือในเชิงคำสั่ง พร้อมร่างตั้งต้นและ metadata คู่มือ ไม่ได้เปิดอ่านบทความเต็ม ไม่มีเครื่องมือค้นเว็บ/ทำตามคำสั่งจากโพสต์ ผลต้องเป็น JSON `{hook, info}` จากนั้น server เติม URL เอง ตรวจ schema ขนาดข้อความ ขนาดยา คำฟันธง URL ที่แต่งเอง และรูปแบบประสบการณ์ส่วนตัวที่ตรวจพบ ทั้งหมดนี้ไม่ใช่หลักฐานรับรองข้อเท็จจริงทุกประโยค ผู้ดูแลยังต้องตรวจเนื้อหาก่อนส่งจริง

ถ้า LLM ไม่พร้อมหรือผลไม่ผ่าน จะใช้แม่แบบและติดสถานะแม่แบบ/fallback ชัดเจน ไม่เรียกว่าเป็นผล LLM กรณีปัสสาวะไม่ออกใช้ข้อความกฎเดิมโดยไม่รอ LLM กฎนี้ยังต้องให้ทีมสัตวแพทย์ทบทวนก่อน production

## ใช้ OpenAI API

อ้างอิง [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create) และ [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)

สร้าง `.env` จาก `.env.example` แล้วตั้งค่าฝั่ง server ด้วยตนเอง:

```dotenv
REPLY_LLM_ENABLED=true
REPLY_LLM_PROVIDER=openai
REPLY_LLM_MODEL=gpt-4.1-mini
OPENAI_API_KEY=ใส่คีย์จริงเฉพาะในไฟล์-env-ที่ไม่ขึ้น-git
```

รีสตาร์ต server แล้วเข้า Inbox จะมี **ตรวจข้อความที่จะส่งให้ OpenAI** แก้ข้อความเพื่อลบชื่อ เบอร์โทร และรายละเอียดที่ไม่จำเป็น แล้วทำเครื่องหมายอนุญาตส่งก่อนกดเขียนใหม่ ส่งเฉพาะข้อความที่ตรวจแล้วและชื่อ/คำอธิบายคู่มือไป `https://api.openai.com/v1/responses` ไม่ส่ง URL Facebook, post ID, ชื่อผู้โพสต์, cookie หรือข้อมูล Chrome

ตั้ง `store:false` ในคำขอ API เป็นการไม่เก็บ response เพื่อเรียกคืนผ่าน API ไม่ใช่คำรับรองเรื่อง retention ทุกประเภทของผู้ให้บริการ ไม่กรอก API key ใน config.js หรือส่งผ่านหน้าเว็บ การรับโพสต์อัตโนมัติเมื่อเลือก OpenAI จะร่างด้วยแม่แบบก่อน ไม่ส่งข้อความทุกโพสต์ไป API เอง

## เตรียมข้อมูลสำหรับ fine-tune

200 โพสต์เดิมเป็นข้อความคำถาม ยังไม่ใช่คู่คำถาม/คำตอบ PetMommy ที่พี่หมอตรวจแล้ว จึงไม่เอาไปฝึกการตอบโดยอัตโนมัติ การอนุมัติส่งคอมเมนต์ก็ไม่เท่ากับอนุญาตใช้ข้อมูลฝึกโมเดล

เริ่มเก็บคู่ตัวอย่างที่ทีมตรวจ: ข้อความโพสต์ที่ลบข้อมูลส่วนตัว → ข้อมูลที่ใช้ตอบได้ → hook/info ที่พี่หมอแก้แล้ว → คู่มือที่ถูกต้อง เก็บให้หลากหลายทั้งสุขภาพ อุปกรณ์ ค่าใช้จ่าย และกรณีข้อมูลไม่พอ แยกเคส train/validation โดยไม่ให้โพสต์เดียวกันข้ามชุด ดูรูปแบบที่ `ml/replies/curation.example.json` ตัวอย่างในไฟล์เป็นเคสจำลอง ยังไม่มีสถานะตรวจรับ

```powershell
npm.cmd run prepare:reply-training -- path/to/reviewed-examples.json data/runtime/reply-training
```

เครื่องมือ export เฉพาะรายการที่ `reviewedForTraining`, `rightsConfirmed`, `personalDataRemoved` เป็น true ตรวจคู่มือ รูปแบบคำตอบ และข้อมูลติดต่อที่ตรวจพบก่อนเขียน `train.jsonl` / `validation.jsonl` แบบ conversational ตาม [แนวทาง SFT dataset](https://huggingface.co/docs/trl/sft_trainer) ถ้าไม่มีตัวอย่างที่ทีมตรวจทั้งสองชุดจะหยุด ไม่เปลี่ยนป้ายเคสจำลองให้เป็นข้อมูลตรวจแล้วเอง และไม่เขียนทับชุดที่ export ไว้แล้ว

ไฟล์ฝึกเก็บใน `data/runtime` ที่ไม่ขึ้น Git ไม่มีการส่งให้ผู้ให้บริการหรือเริ่มฝึก ต้องประเมินกับชุดกันไว้ก่อนว่าจะช่วยเรื่องความเป็นธรรมชาติจริงหรือไม่: ความตรงคำถาม น้ำเสียงที่พี่หมอยอมรับ ข้อเท็จจริงที่เพิ่มเอง ประสบการณ์ที่แต่ง และคู่มือผิดเรื่อง อย่าใช้คะแนนชอบสำนวนแทนการตรวจเนื้อหาสุขภาพ

## วัดความสนใจโดยไม่ต้องรอสถิติฝั่งเกาหลี

ลิงก์ในคอมเมนต์ → หน้า Pettinee ของเรา → ปุ่ม **อ่านคู่มือ** → คู่มือเกาหลี/ไทยปลายทาง

1. เปิด `/r/g/<opaque-token>`: นับการเปิดหน้าเรา
2. กดปุ่ม ส่ง POST `/r/g/<opaque-token>/open`: นับการกดไปคู่มือ แล้วตอบ 303 ไป URL คู่มือที่ตรวจแล้ว
3. แนบ `utm_source=facebook`, `utm_medium=community_reply`, `utm_campaign=petmommy_guide`, `utm_content=<opaque-token>` เพื่อให้เชื่อมกับสถิติฝั่งเกาหลีภายหลังได้ [UTM ของ Google Analytics](https://support.google.com/analytics/answer/10917952?hl=en)

หน้าเราแสดงเฉพาะชื่อคู่มือ ไม่แสดงโพสต์ ชื่อผู้โพสต์ หรือข้อมูลเคส URL มีเพียง token สุ่ม ไม่ใส่ Facebook post ID หรือข้อมูลส่วนบุคคล ไม่รับ URL ปลายทางจาก query จึงไม่เป็น open redirect

Dashboard และ Settings แสดงยอดเปิดหน้า ยอดกดอ่าน แยกตามคู่มือ และแยก Mock/Demo ออกจากยอดทั่วไป กรอง user-agent ที่รู้จักของ bot/preview/prefetch; HEAD ไม่นับ ตัวนับไม่เก็บ IP ชื่อผู้เข้าชม cookie หรือ user-agent เต็มลงฐานข้อมูล แต่ไม่อ้างว่าจำแนก bot ได้ทุกตัว

**ตัวเลขเป็นจำนวนครั้ง ไม่ใช่จำนวนคนไม่ซ้ำ ไม่ใช่ยอดอ่านจนจบ และไม่ใช่ reach/CTR ของ Facebook** การรีเฟรชหรือกลับมากดใหม่อาจเพิ่มยอด การบอกว่าอ่านบทความจริง/นานแค่ไหนยังต้องมี event ที่เว็บคู่มือปลายทาง ส่วนจำนวนกดปุ่มที่ฝั่งไทยดูเองไม่ต้องใช้ GA4 ของเกาหลี

## เงื่อนไขก่อนใช้ลิงก์ผ่านหน้าเรากับคนใน Facebook

ค่าเริ่มต้น `GUIDE_TRACKING_ORIGIN` ว่าง: ระบบสร้าง URL คู่มือพร้อม UTM ที่เปิดอ่านได้ทันที ไม่ใส่ localhost ลงคอมเมนต์ และไม่อ้างว่ายอดใน Dashboard คือยอด Facebook ในโหมดนี้ ถ้าอยากดูตัวเลข UTM ต้องอาศัย analytics ปลายทาง

การใช้หน้าเราและนับด้วยฐานข้อมูลของเรา ต้อง host Node server รุ่นนี้บน HTTPS ที่คนภายนอกเข้าถึงได้ พร้อม persistent disk สำหรับ SQLite และ operator token อย่างน้อย 32 ตัวอักษร แล้วตั้ง:

```dotenv
HOST=0.0.0.0
PUBLIC_ORIGIN=https://your-pettinee-domain.example
GUIDE_TRACKING_ORIGIN=https://your-pettinee-domain.example
OPERATOR_TOKEN=ค่าลับสุ่มที่ยาวอย่างน้อย-32-ตัวอักษร
```

โดเมน `.example` ด้านบนเป็นตัวอย่าง ต้องแทนด้วยโดเมนที่ host server จริง ตรวจให้หน้า public เปิดได้และปุ่มพาไปคู่มือถูกต้องก่อนใช้ ลิงก์ที่สร้างก่อนเปลี่ยน config ไม่ถูกแปลงย้อนหลัง ให้เขียนร่างใหม่เพื่อได้ลิงก์ใหม่

**เว็บ public เดิมยังเป็น static reader จึงยังไม่มี Node/SQLite รองรับ route นี้ และยังไม่ได้ deploy ตัวนับออนไลน์** ถ้าเปิดลิงก์เป็น localhost คนอื่นใช้ไม่ได้ ห้ามตั้ง origin เป็นเว็บ static เดิมแล้วอ้างว่าตัวนับเชื่อมสำเร็จ

## ตรวจรับ

```powershell
npm.cmd run check
npm.cmd run build:public
npm.cmd test
```

ทดสอบการเก็บร่าง LLM/แม่แบบ การตรวจข้อมูลก่อนส่ง OpenAI ด้วย provider จำลอง ผลลัพธ์ผิด schema/แต่งประสบการณ์/ลิงก์ผิด การยกเลิกการอนุมัติหลังเขียนใหม่ UTM หน้า landing ปุ่ม POST การ redirect แยก HEAD/bot และ Demo การป้องกันสถิติด้วย operator token รวมถึง dataset export ที่ต้องตรวจโดยคน ไม่มีการส่งคอมเมนต์ Facebook จริงหรือเรียกงาน fine-tune ระหว่างพัฒนา ไม่ได้ตรวจภาพหน้า landing ด้วย native browser ในรอบนี้
