# จับคู่โพสต์กับคู่มือภาษาไทย

เปิดเว็บด้วย `node server.mjs` แล้วเลือกโพสต์ที่นำเข้า จะมีส่วน **คู่มือที่อ่านต่อได้** อัตโนมัติ หรือใช้ปุ่ม **หาคู่มืออ่านต่อ** เพื่อพิมพ์ข้อความเป็นภาษาธรรมชาติ เลือกแมว สุนัข หรือทั้งสองชนิดได้ การนำเข้า Excel, บันทึกโพสต์, ค้นข้อความ และจำแนกความต้องการยังใช้ได้ตามเดิม

ตัวอย่าง `หลังทำหมันวันที่ 5–6 แผลยังดูบวม จึงถามว่าปกติหรือไม่` จับประเด็น **หลังทำหมัน / แผล / บวม** และแสดง [คู่มือการดูแลหลังทำหมันแมว](https://pettinee.meongsiljang.com/th/guide/qa/cat-post-neuter-recovery-care) เป็นอันดับแรกในชุดทดสอบ จุดประสงค์คือพาไปอ่านความรู้ที่เกี่ยวข้อง ไม่ได้ใช้บทความสรุปว่าอาการในโพสต์ปกติหรือผิดปกติ

## ข้อมูลและ ML ที่ใช้จริง

- ตรวจคลัง [QA ภาษาไทย](https://pettinee.meongsiljang.com/th/guide/qa) วันที่ 19 พฤศจิกายน 2026 ครบ 19 หน้า พบ 1,867 URL ไม่ซ้ำ เก็บชื่อ คำอธิบายสั้น หมวด และลิงก์ต้นฉบับ ไม่เก็บเนื้อหาทั้งบทความ บทความตัวอย่างเปิดตรวจชื่อจริงและหัวข้อย่อยเพิ่มเติม ส่วนรายการอื่นตรวจจากหน้าคลัง และระบุ `catalog-listed` ไว้
- ใช้โมเดล pretrained `Xenova/paraphrase-multilingual-MiniLM-L12-v2` ผ่าน Transformers.js 3.8.1, ONNX q8 CPU, mean pooling, normalized embeddings 384 มิติ ข้อมูลโมเดลอ้างอิง [model card](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2) และ [ONNX repository](https://huggingface.co/Xenova/paraphrase-multilingual-MiniLM-L12-v2) ใบอนุญาต Apache-2.0 รหัส revision และ checksum อยู่ใน `models/guide-encoder/manifest.json`
- จัดอันดับด้วย cosine similarity ของเวกเตอร์ความหมาย ร่วมกับ TF-IDF ตัวอักษร 3–4 ตัวและหัวข้อที่ตรวจพบ มีการแปลงคำพูด เช่น “อ้วก” เป็น “อาเจียน” และแยกก่อน/หลังทำหมัน หัวข้อที่แสดงเป็นการตรวจวลี ไม่ใช่ระบบตัดคำภาษาไทยเต็มรูปแบบ
- โมเดลนี้ไม่ได้ฝึกจากป้ายจำแนกความต้องการ 179 รายการ เป็นคนละงานกับ Intent ML ที่เทรนไว้เดิม ไม่มีการฝึกโมเดลภาษาใหม่หรือเรียก LLM เพื่อแต่งคำตอบ
- ขณะใช้งานฝังข้อความและค้นในเครื่อง ไม่เรียก Hugging Face หรือส่งโพสต์ออกภายนอก โหลดน้ำหนักจากดิสก์เท่านั้น ไม่มี API key เมื่อกดเปิดบทความจึงไปเว็บไซต์ต้นฉบับด้วยลิงก์ที่ไม่แนบข้อความเคส
- ใช้ชื่อ/คำอธิบายสั้นเพื่อค้น จึงอาจพลาดรายละเอียดที่อยู่เฉพาะในบทความ แสดงไม่เกินสามลิงก์พร้อมเหตุผล ไม่มีคะแนนความแม่นยำทางการแพทย์ และยังไม่มีชุดประเมิน retrieval ที่ผู้เชี่ยวชาญให้ป้ายครบ

## ติดตั้งใหม่หรืออัปเดตข้อมูล

เครื่องนี้เตรียมครบแล้ว สำหรับเครื่องใหม่:

```powershell
npm.cmd ci
npm.cmd run guides:download
npm.cmd run guides:index
node server.mjs
```

การดาวน์โหลดโมเดลครั้งแรกต้องใช้อินเทอร์เน็ต น้ำหนัก q8 ประมาณ 118 MB และ tokenizer ประมาณ 17 MB สำหรับอัปเดตคลังจากเว็บไซต์ให้รัน `npm.cmd run guides:sync` แล้ว `npm.cmd run guides:index` ก่อนเริ่ม server ใหม่ การ sync ใช้เฉพาะหน้า catalog กับบทความตัวอย่างที่ระบุ จำกัด concurrency และไม่ทำตามคำสั่งในเนื้อหาเว็บไซต์ หาก catalog เปลี่ยนแต่ยังไม่สร้าง index ใหม่ API จะไม่ใช้ดัชนีที่ไม่ตรงกัน

## สรุปก่อนถามต่อ

แสดงข้อความแบบบทสนทนาให้อ่านก่อน ไม่เปิดฟอร์มหลายช่อง เรียบเรียงจากสรุปที่มีอยู่และข้อมูลที่ผู้ใช้จดจริง ไม่เติมชื่อ อาการ หรือสิ่งที่ลองทำเมื่อไม่มีข้อมูล ผู้ใช้กด **แก้ไขข้อความ → คัดลอกข้อความ → เปิด MeongSilJang ภาษาไทย** ได้ โดยสองปุ่มท้ายแยกกัน ลิงก์ปลายทางตั้งใน `config.js` ไม่มีข้อมูลเคสใน URL และยังไม่มีการเชื่อม MetaPet API

ส่วนสรุปโพสต์/ตรวจคอมเมนต์และการร่างข้อความยังใช้แม่แบบ Demo ที่เตรียมไว้ ส่วนการจำแนก Intent และการจัดอันดับคู่มือใช้ ML จริง

## ตรวจการทำงาน

```powershell
npm.cmd run check
npm.cmd test
```

ทดสอบทั้งโมเดลจริงแบบปิดเครือข่าย, ตัวอย่างหลังทำหมัน, ก่อนทำหมัน, คำพูดอ้วก, ข้อความไม่เกี่ยวข้อง, แยกชนิดสัตว์, catalog/index ตรงกัน, API และ DOM ที่ป้องกันข้อความแทรก HTML/ลิงก์ต่างโดเมน รวมถึงผลค้นล่าสุดไม่ถูกคำขอเก่าทับ คะแนนผ่านชุด regression ไม่ใช่การรับรองความแม่นยำทางคลินิก

ทดสอบด้วยตัวเอง: เปิดชุด 200 โพสต์หรือนำเข้า Excel → เลือกโพสต์ → อ่านประเด็นและกดคู่มือต้นฉบับ → เตรียมคำถาม → อ่านข้อความ → กดแก้และคัดลอก → เปิด MeongSilJang แล้ววางด้วยตัวเอง ทดสอบก่อน/หลังทำหมันในหน้าหาคู่มือด้วย

เครื่องมือเบราว์เซอร์สำหรับตรวจภาพหน้าจอไม่พร้อมใช้งานในรอบนี้ การตรวจอัตโนมัติเป็น Node/HTTP และ DOM จำลอง ไม่ได้ยืนยันการจัดวางจากเบราว์เซอร์บนมือถือจริง
